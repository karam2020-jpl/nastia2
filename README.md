# Nastia Beauty

متجر عراقي عربي باتجاه RTL مبني بـ Next.js وTypeScript. يوفر تصفح المنتجات والسلة، ويحفظ المنتجات والطلبات ورسوم التوصيل في SQLite محلي، مع لوحة إدارة محمية.

## التشغيل على Windows (`D:\nastia2`)

يتطلب المشروع **Node.js 22.18 أو أحدث** لأن طبقة SQLite تستخدم `node:sqlite`. لا يحتاج التشغيل المحلي إلى حساب أو خدمة خارجية.

افتح PowerShell:

```powershell
cd D:\nastia2
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm.cmd ci
```

حرر `.env.local` وضع اسم مستخدم وكلمة مرور خاصين بك، ثم شغّل `npm.cmd run dev` وافتح `http://localhost:3000`. لوحة الإدارة في `http://localhost:3000/admin`.

## متغيرات البيئة والترقية

| المتغير | الوصف |
|---|---|
| `ADMIN_USERNAME` | اسم المالك الأول؛ يستخدم عند خلو جدول الحسابات فقط |
| `ADMIN_PASSWORD` | كلمة مرور المالك الأول؛ غيّرها لاحقاً من حسابات الفريق |
| `DATABASE_PATH` | مسار SQLite؛ الافتراضي `./data/nastia.sqlite` |

عند الترقية يصبح حساب الإدارة الحالي المالك الأول تلقائياً. تغيير متغيرات البيئة لاحقاً لا يستبدل حساباً موجوداً أو كلمة مروره. الجلسات القديمة تتطلب تسجيل دخول جديد. لم يعد `ADMIN_SESSION_SECRET` مستخدماً؛ وجوده في إعدادات قديمة لا يضر. لا تحفظ `.env.local` أو قاعدة البيانات في Git.

قبل التحديث أوقف جميع خوادم المشروع وخذ نسخة من مجلد `data` (أو مسار قاعدة البيانات المخصص). الجداول الجديدة تضاف تلقائياً دون حذف المنتجات والطلبات. شغّل نسخة واحدة فقط من الخادم في مجلد المشروع، ولا تشغّل البناء بالتزامن مع خادم التطوير.

## حسابات الفريق والصلاحيات

المالك يفتح **حسابات الفريق** لإنشاء حساب أو تغيير دوره أو تعطيله أو إعادة تعيين كلمة مروره. كلمات المرور الجديدة من 12 إلى 128 محرفاً، وتخزن كتجزئة scrypt مع ملح عشوائي.

| الدور | الصلاحيات |
|---|---|
| المالك | جميع الأقسام والحسابات ورسوم التوصيل وسجل التغييرات |
| مسؤول الطلبات | عرض الطلبات وتغيير حالاتها |
| مسؤول المنتجات | إضافة المنتجات وتعديلها وحذفها وصورها |
| مسؤول المحتوى | تعديل بانر الصفحة الرئيسية |

الصلاحيات تتحقق على الخادم، وليس بإخفاء الأزرار فقط. تعديل الحساب يلغي جلساته فوراً؛ تعديل حسابك يتطلب تسجيل الدخول مجدداً. لا يمكن تعطيل آخر مالك نشط أو سحب دوره. الجلسات عشوائية، يخزن تجزؤها في القاعدة، وتنتهي بعد 8 ساعات؛ تسجيل الخروج يلغيها. حد تسجيل الدخول خمس محاولات لكل اسم مستخدم خلال 15 دقيقة، ويصفّر عند نجاح الدخول. يعرض سجل التغييرات أحدث 200 حدث دون كلمات المرور أو رموز الجلسات.

## صور المنتجات

من **المنتجات ← إضافة منتج** أو تعديل منتج، ارفع حتى **4 صور** بصيغ JPG/PNG/WebP، بحد 4 ميغابايت للصورة. يمكن معاينتها وحذفها وتعيين الرئيسية قبل الحفظ. تظهر الرئيسية في بطاقات المتجر، وباقي الصور في معرض صفحة المنتج. المنتجات القديمة بلا صور تحتفظ بالرسم الافتراضي. يتحقق الخادم من الحجم ونوع وتوقيع الملف ويرفض SVG؛ حفظ المنتج وصوره معاملة واحدة. تحفظ الصور داخل SQLite وتشملها النسخة الاحتياطية. الصور عامة لأنها محتوى المتجر؛ لا ترفع ملفات خاصة.

## التحقق

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
```

بعد البناء شغّل `node scripts/test-admin-http.mjs` للتحقق من الصلاحيات وإلغاء الجلسات ورفع أربع صور وترتيبها وفشل الحفظ الآمن. ويمكن تشغيل اختبار HTTP معزول للبانر عبر `node scripts/test-banner-http.mjs`؛ يستخدم قاعدة مؤقتة وبيانات دخول مولّدة، ويختبر المصادقة والرفع والعرض ورفض البيانات غير الصالحة دون تعديل قاعدة المتجر.

## السلوك والحدود

### إعدادات الصفحة الرئيسية

من لوحة الإدارة اختر **إعدادات الصفحة الرئيسية**. يمكن تعديل العنوان والوصف ونص الزر ورابطه الداخلي ووصف الصورة، ورفع صورة للحاسوب وأخرى للهاتف ثم معاينتها قبل الحفظ.

- مقاسات مقترحة: الحاسوب 1920×800، الهاتف 1080×1350. الصور تملأ مساحة البانر وقد تُقص عند اختلاف النسبة؛ اترك مساحة للنص يمين صورة الحاسوب وأسفل صورة الهاتف.
- JPG وPNG وWebP فقط، حتى 4 ميغابايت لكل صورة. يتحقق الخادم من الحجم وتوقيع الملف ونوعه؛ لا يقبل SVG. يفضّل ضغط الصور لأقل من 500 كيلوبايت.
- الهاتف يستخدم صورة الحاسوب عند عدم رفع صورة مخصصة. إزالة الصورتين تعيد الرسم الافتراضي. التغييرات لا تُنشر قبل الضغط على حفظ.
- النصوص والصور محفوظة في جدول `homepage_banner` داخل قاعدة SQLite الحالية؛ لا تُحذف المنتجات أو الطلبات. النسخة الاحتياطية للقاعدة تشمل صور البانر. يجب توفير قرص دائم عند الاستضافة، ولا تكفي بيئة ملفات مؤقتة.
- الحفظ يتطلب جلسة إدارة صالحة وطلباً من نفس الأصل؛ روابط الزر داخلية فقط. عرض الصور عام لأنها محتوى المتجر. الصفحة الرئيسية تُقرأ ديناميكياً لظهور التغييرات عند إعادة فتحها أو تحديثها دون إعادة البناء.
- لا ترفع صوراً خاصة أو غير مرخّصة. لا تتضمن هذه الميزة خدمة فحص برمجيات خبيثة أو معالجة/إعادة ترميز للصور.

- يتحقق الخادم من المنتج والسعر والخيارات والمخزون ورسوم المحافظة قبل حفظ الطلب، ويخفض المخزون داخل معاملة SQLite.
- لا تظهر رسالة نجاح الطلب إلا بعد حفظ الطلب وبنوده فعليًا.
- جلسة الإدارة محفوظة في cookie من نوع HttpOnly وSameSite=Strict وSecure في الإنتاج، وكل عمليات الإدارة تتحقق منها ومن الدور على الخادم.
- بيانات العميل لا تُحفظ في `localStorage`؛ السلة فقط تُحفظ محليًا.
- لا توجد بوابة دفع أو عملية نشر عام.
- للإنتاج لاحقًا يلزم HTTPS ونسخ احتياطي وتحديد استراتيجية استضافة SQLite أو نقلها إلى قاعدة مُدارة.
