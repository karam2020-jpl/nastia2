# Nastia Beauty

متجر عراقي عربي باتجاه RTL مبني بـ Next.js وTypeScript. يوفر تصفح المنتجات والسلة، ويحفظ المنتجات والطلبات ورسوم التوصيل في SQLite محلي، مع لوحة إدارة محمية.

## التشغيل على Windows (`D:\nastia2`)

يتطلب المشروع **Node.js 22.5 أو أحدث** لأن طبقة SQLite تستخدم `node:sqlite`. لا يحتاج التشغيل المحلي إلى حساب أو خدمة خارجية.

افتح PowerShell:

```powershell
cd D:\nastia2
Copy-Item .env.example .env.local
npm install
```

حرر `.env.local` وضع اسم مستخدم وكلمة مرور قويين وسر جلسة عشوائيًا بطول 32 محرفًا على الأقل. أنشئ السر عبر:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

ثم شغّل `npm run dev` وافتح `http://localhost:3000`. لوحة الإدارة في `http://localhost:3000/admin`.

## متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `ADMIN_USERNAME` | اسم دخول الإدارة المحلي |
| `ADMIN_PASSWORD` | كلمة مرور قوية؛ لا توجد قيمة افتراضية |
| `ADMIN_SESSION_SECRET` | سر عشوائي لتوقيع الجلسة، 32 محرفًا على الأقل |
| `DATABASE_PATH` | مسار SQLite؛ الافتراضي `./data/nastia.sqlite` |

عند غياب بيانات الإدارة أو ضعف سر الجلسة يرفض الخادم تسجيل الدخول. لا تحفظ `.env.local` أو قاعدة البيانات في Git.

## التحقق

```powershell
npm test
npm run typecheck
npm run build
```

## السلوك والحدود

- يتحقق الخادم من المنتج والسعر والخيارات والمخزون ورسوم المحافظة قبل حفظ الطلب، ويخفض المخزون داخل معاملة SQLite.
- لا تظهر رسالة نجاح الطلب إلا بعد حفظ الطلب وبنوده فعليًا.
- جلسة الإدارة موقعة في cookie من نوع HttpOnly وتنتهي بعد 8 ساعات، وكل عمليات الإدارة تتحقق منها على الخادم.
- بيانات العميل لا تُحفظ في `localStorage`؛ السلة فقط تُحفظ محليًا.
- لا توجد بوابة دفع أو عملية نشر عام.
- للإنتاج لاحقًا يلزم HTTPS ونسخ احتياطي وتحديد استراتيجية استضافة SQLite أو نقلها إلى قاعدة مُدارة.
